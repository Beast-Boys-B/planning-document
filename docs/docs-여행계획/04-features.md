> **[QA 감사 정정]** F-여행2~F-여행5의 정책(P) 열이 가리키던 "P-여행1"은 존재한 적 없는 ID였다(원래도 SP-여행1이었지 P-여행1이 아니었음). `05-policy.md`가 이미 "겹침 처리 규칙은 공통 정책으로 승격됨 — P-공22 참고. SP-여행1(겹침 처리, 로컬)은 삭제하고 공통 참조로 대체함"으로 확정해뒀으므로, 위 4개 행을 **P-공22**(`docs/docs-공통/05-policy.md`)를 가리키도록 정정했다. `06-test-matrix.md`(TC-여행1~TC-여행4)는 이미 P-공22 취지를 정확히 반영해두고 있었다.
>
> **[재정정, QA 감사 — 2차]** 위 1차 정정 당시 P-공22를 "네 축 모두 동일하게 적용"으로 잘못 일반화했다. `draft/schemas/여행계획.md` 겹침 처리 규칙 원문(줄48)을 다시 확인한 결과, **축1(목적)·축4(여행 스타일)은 애초에 중복선택 축이라 P-공22("나중 신호 우선") 적용 대상이 아니다** — 좌·우 신호가 동시에 감지되면 겹침 처리 없이 둘 다 반영된다(양쪽 방향 동시 토글). 이 사실은 `06-test-matrix.md`의 TC-여행1(축1)·TC-여행2(축4)에는 이미 정확히 반영돼 있었으나, F-여행2·F-여행5는 아직 "P-공22에 따라 더 나중에 등장한 신호가 채택됨"이라고 반대로 서술하고 있었다. F-여행2·F-여행5를 정정했다. F-여행3(축2, 단일선택 — P-공22 그대로 적용)·F-여행4(축3, P-공22의 명시된 예외 — 05-policy.md·TC-여행4 참고)는 원래 서술이 모순이 아니라 그대로 두되, 참고 근거만 보강했다.
